# 次の Plateau の候補へ移るボタンをツールバーに置く（設計）

## 目的

`4` のキーで次の Plateau の候補へ移る機能（`2026-11-18-plateau-next-candidate-design.ja.md`）は、候補を選んでいるときの右の欄にしか入口がありません。
何も選んでいないときは画面に手がかりがなく、キーを知らない利用者は機能があることに気づけません。

この変更では、上のツールバーにボタンを置き、機能があることと、キーが `4` であることを画面から分かるようにします。

## 目標と、目標にしないこと

目標は次の2つです。

- 何も選んでいないときでも、ツールバーから次の候補へ移れる。
- ボタンの説明で、同じことが `4` でできると分かる。

次のことは目標にしません。

- 初めて使う人向けの案内の吹き出しや、チュートリアルへの追加。
- 次の候補へ移るときの動きを変えること。ボタンは `4` と同じ動きをします。

## 作り方の案

検討した案は3つで、利用者は案 A を選びました。

- **案 A（採用）:** 上のツールバーの「タグ転記モード」の隣にボタンを置く。この fork で足したほかの機能（ダッシュボード、Zoom 14、タグ転記モード）と同じ場所で、いつも同じ位置に見えます。ツールバーは横幅いっぱいで、幅の狭い画面では右端が隠れます。
- **案 B:** 候補が画面にあるときだけ、地図の下に「残り n 件 次へ (4)」の札を重ねる。いちばん気づきやすい一方、地図に新しい部品を重ねます。最初の設計では、この理由で残りの数を右の欄に置きました。
- **案 C:** 何も選んでいないときの左の欄に、ボタンと残りの数を出す。地図は隠れませんが、左の欄を閉じている人には見えず、目も向きにくい場所です。

## 動き

### ボタン

- 位置は、上のツールバーの「タグ転記モード」の隣です。
- 見た目は既存のツールバーのボタンと同じく、アイコンの下に短い名前を出します。名前の横に、今の画面に残っている候補の数を出します（例: 「次の候補 24」）。
- 押すと、`4` を押したときと同じ処理を呼びます。
- マウスを乗せると、「画面の中の次の Plateau の候補を選ぶ」という説明とキー `4` を出します。

数と、移る先の対象は、`4` と同じ集まり（`utilPlateauCandidates` が返す候補）にします。

### 押せないとき

次のときは、ボタンを押せない見た目にし、説明の欄に理由を出します。

- 今の画面に候補が 0 件のとき。
- ズームが 17 未満のとき。
- Rapid のデータのレイヤーを切っているとき、または Plateau のデータセットを有効にしていないとき。

### キーボードの操作の一覧

`4` の項目を、「Plateau のタグの建物を選んでいるとき」の節から「地物を選ぶ」の節（`shortcuts.selecting_features`）へ移します。
`4` は何も選んでいないときにも使えるので、今の節の見出しと合っていないためです。

### 変えないもの

候補を選んでいるときの右の欄の「次の候補へ (4)」のボタンと「画面に残り n 件」は、そのまま残します。

## ここまでで決めたこと

利用者が決めたこと:

- 案 A で作る（2026-11-19）。

私が決めたこと（読んで違えば直します）:

- 候補が 0 件のとき、ズーム 17 未満のとき、データを切っているときは、押せない見た目にして理由を説明の欄に出す。元に戻すボタンなど、Rapid の既存のボタンと同じ扱いです。
- 数は、地図を描き直すたびに数え直す。右の欄ですでに使っている仕組みと同じです。そのぶん、候補を選んでいないときにも処理が増えます。
- キーの一覧での移し先は「地物を選ぶ」の節にする。
