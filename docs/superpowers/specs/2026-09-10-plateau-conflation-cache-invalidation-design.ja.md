# 編集を確定したときに重なりの判定を作り直す設計

- 日付: 2026-09-10
- ブランチ: `fix/plateau-conflation-cache-invalidation`
- 起点: `28996a427`（Pull Request #55 のマージ地点）

## 背景

利用者から転送されたマッパーの報告のうち、「判定に今の状況を反映してほしい」という内容に対応します。

報告の中身は次のとおりです。
すでに OSM にある建物を動かしても、それと重なっている Plateau の候補が消えたり現れたりしません。
報告者はモードを往復させて、候補を作り直させています。

要望として書かれていますが、中身は不具合の報告です。

## 原因

`PlateauService` は重なりの判定の結果を `_plateauConflationCache` に記憶します。
記憶は 2 つの集合に分かれます。
`rejected` は OSM の建物と重なるため隠す候補、`checked` は重ならないため出す候補です。

この記憶を消しているのは 1 か所だけです。
`startAsync()` で購読している `merge` の合図で、編集システムが新しい OSM のデータを取り込んだときに出ます。

編集が確定したときには `stablechange` という別の合図が出ます。
差分が付いていますが、`PlateauService` はこれを購読していません。

そのため、建物を動かしても記憶が残り、候補の表示が古いままになります。
モードを往復させると候補の描画物が作り直され、結果として判定もやり直されます。

## 決めたこと

`PlateauService.startAsync()` に `stablechange` の購読を足します。
受け取った差分に建物に関わる変更が含まれるときだけ、`checked` と `rejected` の両方を消します。

`merge` の購読はそのまま残します。

### 記憶は全部消す

記憶は Plateau の候補の id で引く形です。
OSM の建物の id からは引けないため、当たった候補だけを消すには位置での探索が要ります。

今回は全部消す形にします。
`merge` はタイルを取り込むたびに出ており、そこでも全部消しています。
消したあとの計算量は、すでに起きているものと同じです。

### 建物に関わる変更かどうかの判定

差分から次の 2 つを見ます。

- `difference.complete()` の変更後の地物。
  親の way と relation を含むため、建物の node を動かした場合もここに建物が現れます。
  削除された地物は値が `undefined` になるので飛ばします。
- `difference.changes` の変更前の地物。
  建物を削除した場合と、`building` タグを外した場合は、変更後の地物に建物が現れないためこちらを見ます。

いずれかに `building` タグがあり、値が `no` でないものが 1 つでもあれば消します。

道路や地点だけを編集したときは、どちらにも建物が現れないので記憶は残ります。
判定が見ているのは建物だけなので、記憶を残しても結果は変わりません。

### 描画は要求しない

`MapSystem` は `stagingchange` を受けて `gfx.immediateRedraw()` を呼びます。
この関数は次の tick に描画を予約するだけで、その場では描きません。

`EditSystem._updateChanges()` は `stagingchange` を出した直後に `stablechange` を出します。
記憶を消す処理は予約された描画より前に終わるため、次の描画には間に合います。

取り消しとやり直しも `_updateChanges()` を通るので、同じ経路で動きます。

## 検討して採らなかった案

### すべての編集で作り直す案

差分の中身を見ずに、確定するたびに記憶を消す案です。
実装は最も短くなります。

採りませんでした。
建物と無関係な編集でも、次の描画で表示範囲の候補すべてを計算し直すためです。
東京の密集した場所では表示範囲の候補が 1000 件を超えます。

### 変わった地物の近くだけ作り直す案

変更された地物の範囲で Plateau 側を探索し、当たった候補の記憶だけを消す案です。
作り直す量は最小になります。

採りませんでした。
探索に加えて、relation とそのメンバーの扱いが増え、実装と試験がいちばん重くなるためです。
記憶を全部消す場合の計算量は `merge` ですでに起きているものと同じなので、先にそちらを試します。

### 操作している途中から追従させる案

`stagingchange` を購読して、ドラッグ中も候補を追従させる案です。

採りませんでした。
マウスを動かすたびに表示範囲の候補を計算し直すため、候補の多い場所で描画が引っかかる可能性があります。

## 試験

`test/browser/services/PlateauService.test.js` の `MockEditSystem` は、いま `on()` が何もしません。
購読を記録して合図を出せるように広げます。

足す試験は 5 件です。

1. 建物の way を動かすと記憶が消えます。
2. 建物の node を動かしても記憶が消えます。親をたどることの確認です。
3. 建物を削除すると記憶が消えます。
4. `building` タグを外すと記憶が消えます。
5. 建物と無関係な地物だけを編集したときは記憶が残ります。

各段の 1 件目は、実装の前に失敗することを確認します。

## 変えないもの

高さの転記の経路（`skipConflation`）は判定を通らないため、影響を受けません。

OSM のレイヤーが消えているときの動き（`isAddBlocked`）は変えません。

Plateau 以外のデータセット（mapwithai、esri、overture）の挙動は変えません。

上流の `modules/core/EditSystem.js` と `modules/core/MapSystem.js` には手を入れません。

## この設計で解決しないこと

報告のもう 1 つの内容（隠している建物を薄く描く案）は、この設計に含めません。
報告者への確認の返事待ちのためです。
