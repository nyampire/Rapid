# 次の Plateau の候補へ移るキー（設計）

## 目的

OSM の建物がすでに多く入っている地域では、残っている Plateau の候補を探して選ぶのに手間がかかります。
候補が既存の建物のあいだに散らばっていて、画面を見渡して探す必要があります。
小さい候補は、見えていても押せる範囲が狭く、狙って選びにくくなっています。

利用者は候補を一つずつ航空写真と見比べ、追加するか無視するかを決めています。
今の画面の周りを片付けたら、次の場所へは自分で地図を動かしています。

この変更では、キーを一つ押すと次の候補が選ばれ、地図がその候補に寄るようにします。
探す手間と、小さい形を押す手間を無くすことが目的です。
見比べて決める作業は、今のまま利用者が行います。

## 目標と、目標にしないこと

目標は次の2つです。

- キーを押すと、今の画面の中で次の候補を選び、地図の中央に寄せる。
- 今の画面に残っている候補の数を見せ、この場所を片付け終えたか分かるようにする。

次のことは目標にしません。

- 読み込んでいない場所の候補を探すこと。サーバは、どの候補が OSM に入っているかを知りません。
- 候補をまとめて選んだり、まとめて追加したりすること。利用者は一つずつ確かめているためです。
- 追加や無視のあとに、自動で次の候補へ移ること。追加した建物のタグや高さを続けて直す今の流れを残すためです。

次のようになったら失敗とみなします。

- 地図が勝手に動き、利用者が見ていた場所から離される。
- 追加できない候補や、OSM の建物と重なる候補に移る。

## 作り方の案

検討した案は3つで、利用者は案1を選びました。

- **案1（採用）:** 次の候補へ移るキーを足す。探す手間と押す手間の両方が無くなります。新しいキーを一つ覚える必要があります。
- **案2:** 小さい候補に目印を重ね、押せる範囲を広げる。手間は減りますが、一つずつ探して押す作業は残ります。
- **案3:** 画面の横に残りの候補の一覧を出す。画面の部品が増えるわりに、見比べる作業は案1と変わりません。

案1を選んだのは、一つずつ見比べる今の作業の順番にそのまま合うためです。

## 動き

### 対象にする候補

次へ移る先と残りの数の対象は、地図に描いている Plateau の候補と同じ集まりにします。
つまり、今の画面の中にあり、OSM の建物と重ならず、無視していない候補です。
描く処理と別の条件で選ぶと、画面に無い候補に移ったり、数が合わなくなったりするので、同じ絞り込みを使います。

ただし、数える単位は建物にします。
外形と部品（`building:part`）に分かれて届く建物（`type=building` の relation）は、地図には外形と部品を別々に描きますが、まとめて1件と数えます。
1件の代表は外形にし、外形がもう残っていないときは、残っている部品のうち最初のものにします。
別々に数えると、`4` が同じ建物の外形と部品のあいだを行き来し、残りの数も部品の数だけ多くなるためです。
中庭のある建物（`type=multipolygon` の relation）は、もともと1件として描いているので、そのまま1件です。

### キーを押したとき

- 候補を選んでいるときは、その候補にいちばん近い別の候補へ移ります。選んでいるのが部品のときも、同じ建物の外形と部品はすべて飛ばします。
- 移った先が外形と部品に分かれた建物なら、外形を選びます。
- 何も選んでいないとき、または候補以外を選んでいるときは、地図の中央にいちばん近い候補へ移ります。
- 移るときは、その候補を選んだ状態にし、地図の中央に寄せます。ズームは変えません。
- キーで飛ばした候補は、そのまま残ります。追加も無視もしていないからです。

### 残りの候補の数

候補を選んだときの右の欄に、今の画面に残っている候補の数と、次の候補へ移るボタンを出します。

```
┌ 右の欄 ─────────────────────┐
│ Plateau の建物               │
│ [追加 (A)]  [無視 (D)]       │
│ 次の候補へ (4)  画面に残り 12 件 │
└─────────────────────────────┘
```

候補が残っていないときは、ボタンを押せない状態にし、「この画面に残りの候補はありません」と出します。

### 追加できないとき

OSM のデータのレイヤーを消しているあいだは、候補が OSM の建物と重なるか判定できず、追加もできません。
このあいだは、キーを押しても移らず、今と同じ案内を出します。

## ここまでで決めたこと

利用者が決めたこと:

- 案1で作る。
- 対象は今の画面の中だけにする（利用者は画面の周りを片付けたら自分で次の場所へ動くため）。
- 候補は一つずつ確かめる前提にする。
- 外形と部品に分かれた建物は、まとめて1件と数え、外形を代表にする（2026-11-19 に追加）。部品だけを `4` で選ぶことはできなくなりますが、部品は地図で押せば選べます。
- キーは修飾キーなしの `4` にする。右手をマウスに置いたまま、左手だけで押せるためです。Rapid の既存のキーで `4` は使われていません。隣の `3` を押し間違えると面を描く操作が始まりますが、Esc で取り消せます。

私が決めたこと（読んで違えば直します）:

- 追加や無視のあとに自動で次へ移らず、キーを押したときだけ移ります。
- ズームは変えません。航空写真と見比べやすいズームは利用者が決めているためです。
- 残りの数は、地図の隅ではなく右の欄に出します。新しい部品を地図に重ねずに済むためです。そのぶん、候補を選んでいないときは数が見えません。
- 「いちばん近い」は、候補の外形の中心どうしの距離で決めます。
- キーで飛ばした候補を覚えておく仕組みは作りません。近くの候補を飛ばすと、また同じ候補に戻ることがあります。困るようなら後で足します。

## 作る人に任せること

- 候補の集まりを、描く処理とどう共有するか。
- ボタンの見た目と、日本語と英語の文言の細部。
- テストの書き方。キーの動き、いちばん近い候補の選び方、残りが無いときの動き、追加できないときの動きを確かめることが条件です。
