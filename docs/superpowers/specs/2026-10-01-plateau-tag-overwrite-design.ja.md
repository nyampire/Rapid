# タグ転記で既存の値と PLATEAU の値を選べるようにする設計

- 日付: 2026-10-01
- 関連: `2026-07-17-plateau-height-transfer-design.ja.md`（転記の元の設計）、`2026-07-18-plateau-tags-editor-section-design.ja.md`（タグ転記の欄）

## 背景

タグ転記は、OSM の建物に無いタグだけを足し、既存の値は書き換えません。
`height`、`ele`、`building:levels` のどれかが PLATEAU と食い違う建物では、説明の文だけを出し、適用のボタンを出していません。

元の設計は、既存の値の上書きを第 3 段階に置き、実施するかどうかを OSM の日本のコミュニティとの協議で決めるとしていました。
この設計では、上書きの機能を URL のパラメータで隠したまま先に作って本番に出し、協議の参加者に実物を触ってもらえるようにします。
既定の画面と動作は変えません。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 有効にする方法 | URL に `plateau_overwrite=1` があるときだけ有効にします。 |
| 選ぶ単位 | タグごとに選びます。 |
| 最初の選択 | 「OSM の値」を選んだ状態にします。 |
| 高さの警告がある建物 | 「PLATEAU の値」を選べなくし、理由の文を出します。 |
| 面積が大きく違う組 | 書き換えを出さず、理由の文を出します。 |
| 適用の単位 | 追加と書き換えを 1 回の編集として記録します。 |

最初の選択を「OSM の値」にしたのは、利用者が切り替えない限り既存の値が書き換わらないようにするためです。
A キーで適用したときに、意図しない上書きが起きません。

高さの警告がある建物で書き換えを止めるのは、追加と上書きで失うものが違うためです。
追加は無い値を埋めるだけですが、上書きは既存の値を消します。
追加はこれまでどおり止めません。

面積が大きく違う組（PLATEAU の外形が OSM の建物の 2 倍を超えるもの）は、1 つの外形の中に OSM の建物が何棟かに分けて描かれている場合が多い組です。
街区単位の高さで個々の棟の値を消さないよう、書き換えは面積比が 0.5〜2.0 の組に限ります。

## 画面と動作

URL に `plateau_overwrite=1` が無いときは、今と何も変わりません。
以下は、このパラメータがあるときの動作です。

タグ転記の欄の表に、食い違うタグの行を足します。
各行には、タグの名前と、「OSM の値」と「PLATEAU の値」の 2 つの選択肢を並べます。
OSM に無いタグの行は今と同じ読み取り専用の行で、適用すれば必ず追加されます。

適用のボタンと A キーは、追加するタグがあるか、「PLATEAU の値」を選んだ行が 1 つ以上あるときに有効になります。
食い違うタグだけの建物で、すべて「OSM の値」のままなら、ボタンは無効の表示にし、A キーも割り当てません。

「PLATEAU の値」を選べない場合は、表の上に理由の文を 1 つ出します。

| 場合 | 理由の文（案） | 食い違うタグの行 |
|---|---|---|
| 高さの警告がある | 転記元の建物の高さに警告があるため、既存の値は書き換えられません。 | 選択肢を並べ、「PLATEAU の値」を無効にします。 |
| 面積が大きく違う | 外形の面積が大きく違うため、既存の値は書き換えられません。 | 選択肢を出さず、2 つの値の対比だけを出します。 |

両方に当たるときは、面積の文だけを出します。
面積の不一致では行の形が変わり、警告の有無にかかわらず書き換えられないためです。

高さの警告の文は、今と同じ位置にこれまでどおり出します。
理由の文は、警告の文とは別に、書き換えられないことだけを伝えます。

適用した建物は、今と同じく転記の候補から外れます。
地図の印（食い違いの黄色の「!?」など）は変えません。

## 部品の分け方

変更する部品は 4 つで、新しいファイルは作りません。

### 転記の操作（`modules/actions/transfer_plateau_tags.js`）

`actionTransferPlateauTags(entityID, addTags, replaceTags)` にします。
`addTags` は今と同じく、OSM に値があるキーを飛ばします。
`replaceTags` は、OSM の値を渡された値で置き換えます。
`replaceTags` を省いたときは今と同じ動作になるので、既存の呼び出しはそのまま動きます。

### 候補の計算部分（`modules/modes/HeightTransferMode.js`）

次の 3 つを足します。

- 建物ごとの選択の状態。
  PLATEAU の建物の id ごとに、「PLATEAU の値」を選んだタグの集合を持ちます。
  候補から外れた建物の分は、候補を計算し直すときに捨てます。
  選択を切り替える公開の関数を用意し、切り替えたら `change` を知らせます。
- 書き換えられるかの判定。
  URL のパラメータが無い、面積の不一致、高さの警告のいずれかなら書き換えられないとし、理由を返します。
  理由は「パラメータ無し」「面積」「警告」の 3 通りで、面積を警告より先に調べます。
  高さの警告の有無は、既存の `utilPlateauHasTransferWarning` で調べます。
  URL のパラメータは、API の接続先の指定（`plateau_api_url`）と同じく `window.location.hash` から読みます。
- 適用の処理。
  選択の状態から書き換えるタグを集め、追加と合わせて 1 回の編集として記録します。
  編集の注記に、書き換えたタグの名前（`overwrittenKeys`）を残します。
  A キーを割り当てる条件を、「追加するタグがある」から「追加するタグがあるか、PLATEAU の値を選んだタグがある」に広げます。
  ボタンの有効と無効も、同じ条件を使います。

### タグ転記の欄（`modules/ui/sections/plateau_tags.js`）

食い違うタグの行と理由の文を描きます。
選択が変わったら、候補の計算部分の公開の関数を呼びます。
欄は選択の状態を自分では持たず、候補の計算部分から読みます。
このため、ボタンと A キーの結果は一致します。

今の欄は、食い違いの状態で追加するタグが無いと表を出さずに終わります。
パラメータがあるときは、食い違うタグの行があれば表を出すようにします。

### 突き合わせの部分（`modules/core/lib/HeightTransferMatcher.js`）

変えません。
食い違うタグの一覧（`conflictingTags`）は、今も候補に入っているためです。

## データの流れ

利用者が行の選択を切り替えると、欄が候補の計算部分の選択の状態を書き換えます。
候補の計算部分が `change` を知らせ、欄が描き直されます。

適用すると、候補の計算部分が操作を 1 回実行して記録します。
記録の時点で `stablechange` が出て候補が計算し直され、その建物は候補から外れます。

## 失敗したときの扱い

適用の直前に、書き換えるタグを候補の今の `conflictingTags` と照らし、一覧に無いタグは書き換えません。
欄を表示したあとに利用者が OSM の値を手で直した場合、候補は計算し直されますが、選択の状態に古いタグが残りうるためです。

適用の時点で書き換えられない状態になっていれば、書き換えは行わず、追加だけを行います。
適用の時点で建物が消えていれば、今と同じく何もしません。

取り消しは、追加と書き換えを 1 回でまとめて戻します。
やり直しも同じ単位です。

URL のパラメータは、地図を動かしたあとも URL に残る必要があります。
`plateau_api_url` は残っていますが、実装の最初に `plateau_overwrite` でも同じであることを確かめます。

## 試験

転記の操作の試験（`node --test` で 1 ファイルずつ回すもの）で、次を確かめます。

- 書き換えるタグが、OSM の値を置き換えること
- 追加と書き換えを同時に渡したときに、両方が反映されること
- 3 つ目の引数を省いたときに、今と同じく既存の値を書き換えないこと
- 取り消しで、元の値に戻ること

候補の計算部分の試験（ブラウザの試験）で、次を確かめます。

- 書き換えられるかの判定の 4 通り（可、パラメータ無し、面積、警告）と、面積と警告の両方に当たるときに面積を返すこと
- 選択の状態が保持され、候補から外れた建物の分が捨てられること
- A キーを割り当てる条件
- 適用の直前に、食い違いの一覧に無いタグを書き換えないこと
- 注記に `overwrittenKeys` が残ること

タグ転記の欄の試験（ブラウザの試験）で、次を確かめます。

- パラメータが無いときに、表示が今と同じであること
- 最初は「OSM の値」が選ばれていること
- 理由の文の出し分けと、面積の不一致では選択肢を出さないこと
- ボタンの有効と無効

最後に、手元のエディタで食い違いのある建物を選んで書き換え、取り消しで戻ることを目で確かめます。

## 公開の手順

本番には、パラメータで隠したまま出します。
協議で受け入れられたら、パラメータを外す変更を別の Pull Request にします。

## 対象外

- 地図の印の変更
- 複数の建物をまとめて書き換える機能
- 保存の前の「問題」の一覧で、書き換えた建物をもう一度知らせること
