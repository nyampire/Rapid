# タグ転記で既存の値と PLATEAU の値を選べるようにする設計

- 日付: 2026-10-01（2026-10-03 に画面の形を改訂）
- 関連: `2026-07-17-plateau-height-transfer-design.ja.md`（転記の元の設計）、`2026-07-18-plateau-tags-editor-section-design.ja.md`（タグ転記の欄）

## 背景

タグ転記は、OSM の建物に無いタグだけを足し、既存の値は書き換えません。
`height`、`ele`、`building:levels` のどれかが PLATEAU と食い違う建物では、説明の文だけを出し、適用のボタンを出していません。

元の設計は、既存の値の上書きを第 3 段階に置き、実施するかどうかを OSM の日本のコミュニティとの協議で決めるとしていました。
この設計では、上書きの機能を URL のパラメータで隠したまま先に作って本番に出し、協議の参加者に実物を触ってもらえるようにします。
既定の画面と動作は変えません。

## 改訂の経緯

最初の版では、食い違うタグの行を別の表に足し、行ごとにラジオボタンで選ぶ形にしていました。
実装して手元のエディタで確かめたあと、表を 1 つにまとめ、すべてのタグの行に「OSM」と「Plateau」のボタンを置く形に改めました。
同時に、OSM に値が無いタグの行でも「OSM」を選べるようにし、そのタグを追加しない選び方をできるようにしました。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 有効にする方法 | URL に `plateau_overwrite=1` があるときだけ有効にします。 |
| 選ぶ単位 | タグごとに選びます。 |
| 画面の形 | 1 つの表に、OSM に無いタグと食い違うタグを 1 行ずつ並べ、表の上に「OSM」と「Plateau」の見出しを置きます。各行の 2 つのボタンには値だけを書きます。 |
| OSM に無いタグの最初の選択 | 「Plateau」です。「OSM」を選ぶと、そのタグは追加しません。 |
| 食い違うタグの最初の選択 | 「OSM」です。「Plateau」を選ぶと、適用したときに値が書き換わります。 |
| 選んだボタンの見た目 | 選んだボタンを濃い色で塗り、もう一方は白のままにします。同じ行のもう一方を押すまで変わりません。 |
| 高さの警告がある建物 | 食い違うタグの「Plateau」のボタンを押せなくし、理由の文を出します。 |
| 面積が大きく違う組 | 食い違うタグの「Plateau」のボタンを押せなくし、理由の文を出します。 |
| 適用の単位 | 追加と書き換えを 1 回の編集として記録します。 |
| パラメータが無いとき | 今と同じ表示（ボタンの無い、追加するタグだけの表）のままにします。 |

食い違うタグの最初の選択を「OSM」にしたのは、利用者が切り替えない限り既存の値が書き換わらないようにするためです。
A キーで適用したときに、意図しない上書きが起きません。
OSM に無いタグの最初の選択を「Plateau」にしたのは、切り替えない限り今と同じ結果（無いタグはすべて追加）になるようにするためです。

高さの警告がある建物で書き換えを止めるのは、追加と上書きで失うものが違うためです。
追加は無い値を埋めるだけですが、上書きは既存の値を消します。
OSM に無いタグの行は、警告があってもどちらのボタンも押せます。

面積が大きく違う組（PLATEAU の外形が OSM の建物の 2 倍を超えるもの）は、1 つの外形の中に OSM の建物が何棟かに分けて描かれている場合が多い組です。
街区単位の高さで個々の棟の値を消さないよう、書き換えは面積比が 0.5〜2.0 の組に限ります。

パラメータが無いときは、OSM に無いタグの行にもボタンを出しません。
見た目の変更も、協議の参加者に試してもらってから広げるためです。

## 画面と動作

URL に `plateau_overwrite=1` が無いときは、今と何も変わりません。
以下は、このパラメータがあるときの動作です。

例として、OSM の建物に `building:levels=2` だけがあり、PLATEAU の建物に `height=8.2`、`ele=6.4`、`building:levels=1` がある場合を示します。

```
                 OSM      Plateau
height           [なし ]  [■8.2 ]
ele              [なし ]  [■6.4 ]
building:levels  [■2   ]  [ 1   ]
                                    [適用]
```

`■` は塗られた（選ばれた）ボタンを表します。
表の行は、OSM に無いタグと食い違うタグを、`height`、`ele`、`building:levels` の順に並べます。
OSM と PLATEAU で値が同じタグは、行を出しません。
OSM に値が無いタグの「OSM」のボタンには「なし」と書きます。

これまでの「Plateauから追加」の見出しと、食い違いの注記（`conflict_note`）は、パラメータがあるときは出しません。
表の見出しと行が、その代わりになります。
面積の注意の文（`area_mismatch_note`）と高さの警告の文は、これまでどおり出します。

適用のボタンと A キーは、「Plateau」が選ばれた行が 1 つ以上あるときに有効になります。
ただし、書き換えられない建物では、食い違うタグの行は数えません（その行の「Plateau」は選べないため）。
すべての行で「OSM」が選ばれているときは、ボタンは押せない表示にし、A キーも割り当てません。

食い違うタグの「Plateau」のボタンを押せない場合は、表の上に理由の文を 1 つ出します。

| 場合 | 理由の文 |
|---|---|
| 高さの警告がある | 転記元の建物の高さに警告があるため、既存の値は書き換えられません。 |
| 面積が大きく違う | 外形の面積が大きく違うため、既存の値は書き換えられません。 |

両方に当たるときは、面積の文だけを出します。

選んだボタンの色は、エディタの既定のボタンの見た目に上書きされないよう、この欄の規則で直接指定します。
選んだ状態は `aria-pressed` でも示します。

選んだ状態は、別の建物を選んでから戻っても残ります。
適用したとき、地図を動かしてその建物が転記の候補から外れたとき、タグ転記の機能を切ったときに消えます。
適用したあとに取り消すと、最初の状態に戻ります。

適用した建物は、今と同じく転記の候補から外れます。
地図の印（食い違いの黄色の「!?」など）は変えません。

## 部品の分け方

変更する部品は 4 つで、新しいファイルは作りません。

### 転記の操作（`modules/actions/transfer_plateau_tags.js`）

`actionTransferPlateauTags(entityID, addTags, replaceTags)` にします。
`addTags` は今と同じく、OSM に値があるキーを飛ばします。
`replaceTags` は、OSM の値を渡された値で置き換えます。
`replaceTags` を省いたときは今と同じ動作になるので、既存の呼び出しはそのまま動きます。

### 候補の計算部分（`modules/modes/HeightTransferMode.js`）

次の 4 つを持ちます。

- 書き換えられるかの判定（`getOverwriteBlock`）。
  URL のパラメータが無い、面積の不一致、高さの警告のいずれかなら書き換えられないとし、理由を返します。
  理由は「パラメータ無し」「面積」「警告」の 3 通りで、面積を警告より先に調べます。
  高さの警告の有無は、既存の `utilPlateauHasTransferWarning` で調べます。
  URL のパラメータは、API の接続先の指定（`plateau_api_url`）と同じく `window.location.hash` から読みます。
- 建物ごとの選択の状態。
  PLATEAU の建物の id ごとに、利用者が押したボタンを「タグの名前と、`'osm'` か `'plateau'`」の組で覚えます。
  押していないタグは覚えず、最初の選択（OSM に無いタグは `'plateau'`、食い違うタグは `'osm'`）とみなします。
- 選択を読み書きする関数。
  `getChoice(candidate, key)` は、そのタグで選ばれているボタンを返します。
  パラメータが無いときは、OSM に無いタグには必ず `'plateau'` を返します（今と同じく必ず追加するため）。
  書き換えられない建物の食い違うタグには、覚えた選択にかかわらず `'osm'` を返します。
  `setChoice(candidate, key, source)` は、押されたボタンを覚え、`change` を知らせます。
  パラメータが無いとき、書き換えられない建物の食い違うタグに `'plateau'` を渡されたとき、表に無いタグを渡されたときは、何もしません。
- 適用の処理。
  `getChoice` が `'plateau'` を返すタグのうち、OSM に無いものを追加に、食い違うものを書き換えに振り分け、1 回の編集として記録します。
  編集の注記に、書き換えたタグの名前（`overwrittenKeys`）を残します。
  `hasWorkToApply(candidate)` は、追加か書き換えに回るタグが 1 つでもあれば真を返します。
  A キーの割り当てと、欄のボタンの有効と無効は、どちらもこの関数を使います。

最初の版で作った `getOverwriteKeys` と `setOverwrite`（食い違うタグだけを扱う関数）は、`getChoice` と `setChoice` に置き換えます。

### タグ転記の欄（`modules/ui/sections/plateau_tags.js`）

パラメータがあるときは、見出しの行と、タグごとの 2 つのボタンの行を描きます。
ボタンを押したら、候補の計算部分の `setChoice` を呼びます。
欄は選択の状態を自分では持たず、`getChoice` で読みます。
このため、ボタンと A キーの結果は一致します。

パラメータが無いときは、今の表（読み取り専用の、追加するタグだけの行）を描きます。

### 突き合わせの部分（`modules/core/lib/HeightTransferMatcher.js`）

変えません。
OSM に無いタグ（`missingTags`）と食い違うタグ（`conflictingTags`）は、今も候補に入っているためです。

## データの流れ

利用者がボタンを押すと、欄が候補の計算部分の `setChoice` を呼びます。
候補の計算部分が選択を覚えて `change` を知らせ、欄が `getChoice` を読んで描き直します。

適用すると、候補の計算部分が操作を 1 回実行して記録します。
記録の前にその建物の選択を捨て、記録の時点で `stablechange` が出て候補が計算し直され、その建物は候補から外れます。

## 失敗したときの扱い

適用のときは、その時点の候補の `missingTags` と `conflictingTags` から、追加と書き換えを決め直します。
欄を表示したあとに利用者が OSM の値を手で変えた場合でも、覚えた選択は「タグの名前」で引くので、変わったあとのタグの種類に合わせて使われます。
たとえば、`ele` で「OSM」を選んだあとに OSM の `ele` に値を入れると、`ele` は食い違うタグになり、覚えた `'osm'` のまま「書き換えない」になります。

適用の時点で書き換えられない状態になっていれば、書き換えは行わず、追加だけを行います。
適用の時点で建物が消えていれば、今と同じく何もしません。

取り消しは、追加と書き換えを 1 回でまとめて戻します。
やり直しも同じ単位です。

URL のパラメータは、地図を動かしたあとも URL に残ります。
エディタの URL の管理は、知らないパラメータを消さず、決まった数個（`comment`、`source` など）だけを外すためです。

## 試験

転記の操作の試験（ブラウザの試験、既存の `test/browser/actions/transfer_plateau_tags.test.js`）で、次を確かめます。
この部分は最初の版から変えません。

- 書き換えるタグが、OSM の値を置き換えること
- 追加と書き換えを同時に渡したときに、両方が反映されること
- 3 つ目の引数を省いたときに、今と同じく既存の値を書き換えないこと
- 取り消しで、元の値に戻ること

候補の計算部分の試験（ブラウザの試験）で、次を確かめます。

- 書き換えられるかの判定の 4 通り（可、パラメータ無し、面積、警告）と、面積と警告の両方に当たるときに面積を返すこと
- `getChoice` の最初の選択（OSM に無いタグは `'plateau'`、食い違うタグは `'osm'`）
- パラメータが無いときに、OSM に無いタグが必ず `'plateau'` になること
- 書き換えられない建物の食い違うタグが、覚えた選択にかかわらず `'osm'` になること
- `setChoice` が選択を覚えて `change` を知らせること、書き換えられない場合と表に無いタグでは何もしないこと
- 候補から外れた建物と、機能を切ったときに、選択が捨てられること
- 適用で、OSM に無いタグのうち「OSM」を選んだものを追加しないこと
- 適用で、食い違うタグのうち「Plateau」を選んだものを書き換え、注記に `overwrittenKeys` が残ること
- 選んだあとに OSM の値が変わったときに、タグの名前で選択が引き継がれること
- `hasWorkToApply` と A キーの割り当てが、すべて「OSM」のときに偽になること

タグ転記の欄の試験（ブラウザの試験）で、次を確かめます。

- パラメータが無いときに、表示が今と同じであること
- 見出しの行に「OSM」と「Plateau」が出て、各行のボタンに値だけが書かれること
- OSM に値が無いタグの「OSM」のボタンに「なし」が出ること
- 最初の選択と、押したボタンだけが選ばれた見た目（と `aria-pressed`）になること
- 理由の文の出し分けと、書き換えられない建物で食い違うタグの「Plateau」が押せないこと
- 適用のボタンの有効と無効

最後に、手元のエディタで次を目で確かめます。

- 選んだボタンが塗られ、同じ行のもう一方を押すまで変わらないこと
- 食い違うタグを書き換え、OSM に無いタグの一部を追加しない選び方で適用し、1 回の取り消しで戻ること

## 公開の手順

本番には、パラメータで隠したまま出します。
協議で受け入れられたら、パラメータを外す変更を別の Pull Request にします。

## 対象外

- 地図の印の変更
- 複数の建物をまとめて書き換える機能
- 保存の前の「問題」の一覧で、書き換えた建物をもう一度知らせること
- 読み込み直したあとも選択を残すこと
